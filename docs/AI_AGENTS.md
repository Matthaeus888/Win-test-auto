# AI 에이전트 기반 QA 프로세스 설계

이 프로젝트의 핵심은 "AI가 테스트 코드를 대신 짜준 것"이 아니라, **QA 프로세스의 각
단계를 단일 책임 원칙에 따라 나누고, 사람의 승인이 반드시 필요한 지점을 코드/규칙
수준에서 강제한 것**이다. 아래는 그 설계를 정리한 문서다.

## 왜 하나의 AI가 처음부터 끝까지 하지 않는가

PRD를 쓰는 사람과 TC를 쓰는 사람, 코드를 리뷰하는 사람이 같으면 자기 검증의 함정에
빠지기 쉽다. 이 프로젝트는 이를 방지하기 위해 역할을 5개 Sub Agent로 명시적으로
분리했다([`.claude/agents/`](../.claude/agents/)).

| Agent | 단일 책임 | 입력 (Source of Truth) | 출력 |
|---|---|---|---|
| `prd-agent` | Project/Feature PRD 작성 | 사용자 인터뷰, 실제 사이트 확인 | `docs/prd/**.md` |
| `tc-agent` | 승인된 PRD 기반 Test Case 작성 | 승인된 PRD | `docs/tc/**.md` + Google Sheet |
| `automation-candidate-agent` | 자동화 대상 1차 평가·확정 | 승인된 TC | `docs/tc/automation-candidates/**.md` |
| `roadmap-agent` | Phase별 구현 순서 설계 | 승인된 TC + 자동화 대상 확정 | `docs/roadmap/ROADMAP.md` |
| `automation-developer-agent` | 자동화 코드 구현 + 테스트 실행 | 승인된 Roadmap | `automation/**` |

각 Agent는 **자신의 산출물만** 만들고, 상위 단계에서 이미 승인된 산출물을 임의로
수정하지 않는다 — 예를 들어 자동화 구현 Agent가 코드를 짜다가 "TC 내용이 실제 사이트
동작과 다르다"는 것을 발견해도, TC 문서를 직접 고치지 않고 **사용자에게 보고한 뒤
재승인을 받아야 반영**된다(아래 "실제로 있었던 충돌 사례" 참고).

## 사람이 반드시 승인해야 하는 5가지 지점

아래는 워크플로우상 몇 번째 단계인지와 무관하게, **항상** 사람의 명시적 승인이 있어야
다음 단계로 넘어가도록 설계했다.

1. Project/Feature PRD 확정
2. TC 자동화 대상 최종 선정
3. Git Commit
4. Git Push
5. (Production 데이터에 영향을 주는 검증이 필요한 경우) 그 실행 자체

AI는 초안·추천까지만 하고, **확정은 항상 사람의 몫**이라는 원칙을 문서(`CLAUDE.md`
18절)로 고정하고, 모든 Agent가 이 문서를 최상위 지침으로 따르도록 설계했다.

## 실제로 있었던 충돌·재승인 사례

이 설계가 실제로 작동했음을 보여주는 사례:

- **product-search 기능 구현 중**, 실제 사이트의 검색 매칭 로직이 이미 승인된 PRD/TC
  내용과 다르다는 것을 자동화 구현 단계에서 발견했다. 자동화 구현 Agent는 코드를
  실제 동작에 맞춰 임의로 만들지 않고, PRD/TC를 사람에게 재확인받아 **2차례 재정정**한
  뒤에야 구현을 진행했다(`docs/roadmap/ROADMAP.md` Phase 4 진행 현황 참고).
- **회원가입 기능 구현 중**, 승인된 TC의 기대 동작(계정 삭제 후 재로그인 시도)이 실제
  사이트 동작(삭제 직후 자동 로그인됨)과 달라, 이 역시 사용자 확인 후 TC/PRD를
  갱신했다.

두 사례 모두 "일단 실제 동작에 맞춰 테스트를 통과시키자"는 유혹을 거부하고, **산출물
간 불일치를 발견 즉시 보고 → 재승인 → 반영**하는 원칙(`CLAUDE.md` 7·8절)을 지킨
과정이다.

## Source of Truth 계층

산출물 간 내용이 충돌할 수 있으므로, 판단 기준의 우선순위를 명시적으로 고정했다.

| 판단 기준 | Source of Truth |
|---|---|
| 요구사항 | 승인된 PRD |
| Test Scenario | 승인된 TC |
| 자동화 구현 범위 | 승인된 TC + 승인된 Roadmap |
| 실제 구현 상태 | Repository Code |
| CI 실행 결과 | GitHub Actions Result |

## 이 설계에서 증명하려는 것

- AI 에이전트를 "무엇이든 다 하는 하나의 도구"가 아니라, **역할·책임·승인 경계가
  명확한 협업 구조**로 설계할 수 있다.
- AI가 결정을 대신 내리는 것이 아니라, **결정에 필요한 근거를 정리해 사람에게
  올리고, 사람이 확정한 결정을 정확히 실행**하도록 만들 수 있다.
- 이 원칙은 특정 프로젝트에 종속되지 않고 [`CLAUDE.md`](../CLAUDE.md) 하나의 문서로
  고정되어 있어, 새로운 Sub Agent가 추가되어도 동일한 규율 아래 동작한다.
